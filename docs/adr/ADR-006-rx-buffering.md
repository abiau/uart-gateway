# ADR-006：RX Buffer、Replay、Gap 與錄製

## 背景與問題

UART Reader（接收工作路徑）不能因某個 Client（用戶端）或磁碟慢而停止。SSH Tunnel 中斷後需要判斷能否恢復歷史；Record（紀錄）不能在已掉資料時仍宣稱完整。

## 可選方案與優缺點

| 方案 | 優點 | 缺點 |
| --- | --- | --- |
| 無界記憶體 Buffer（緩衝） | 看似容易保存全部歷史 | 長時間流量會耗盡記憶體 |
| 全同步落盤再廣播 | 資料流程直觀 | 磁碟卡住就影響 UART 接收 |
| 有界 Ring + 每訂閱 Queue + 非同步 Recorder | 控制資源，隔離慢速接收者與磁碟 | 必須明確回報缺口與保留邊界 |

## 最終建議與選擇原因

每 Channel（通道）獨立 Ring Buffer（環狀緩衝區），每 Subscription（訂閱）與 Connection（連線）各有有界 Queue（佇列）。Replay（重播）使用 Instance／Epoch／Offset（執行個體／世代／位移）恢復，明確區分 replay 與 live（即時）。

預設遇 Gap（資料缺口）回錯誤或終止訂閱；只有顯式選擇 skip（略過）才跨越已知缺口，且先送 Gap Event（事件）。未知連續性必須終止 Epoch，不偽造精確的遺失範圍。

原因是無法同時保證有限記憶體、任意慢 Client 與永不掉資料；系統應保持 UART 接收並誠實呈現各使用端完整性。

## 技術影響

候選 Ring 為每通道 4 MiB，在 115200／8N1 約容納 6 分鐘原始資料，實際含物件成本且不是固定時間承諾。Replay 不能無限保留已淘汰區塊的引用。

Recorder（錄製器）位於 Gateway，與 Client 生命週期分開，使用有界 Queue 與容量／年齡輪替。候選常駐錄製預設關閉，啟用後建議 7 天且每通道 1 GiB；此取捨避免未確認就保存敏感資料，但長斷線可能超出 Ring。

Capture（擷取紀錄）保存 Binding Snapshot（綁定快照）、設定、Epoch、已知缺口與正常結束狀態。磁碟滿、Queue 溢位或程序崩潰使完整性不完整或未知；不能只寫一般 Log 而仍回覆錄製正常。

Gateway 的序號不能偵測所有 UART／USB／Driver 前段遺失，不宣稱無法證明的零遺失。

## 未來變更條件

若使用者要求更長斷線保留、可搜尋歷史或經量測的持久性保證，再設計磁碟 Replay、索引或刷新政策。不能把即時 Ring API 偷偷變成不受限歷史查詢。
