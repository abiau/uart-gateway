# UART Gateway 通訊協定 V1

> 核准更新（2026-11-03）：使用者已在本次對話接受全部建議答案，核准 Phase 0 文件與建議基線。下文「候選／建議／待核准」保留設計來源與理由，現已作為初始採用值；不代表硬體或網路已驗證。Q-11 接線與 UART 參數已由使用者確認；Q-12～Q-14、Q-17 的現場資訊仍待取得。目前實作與驗證進度以專案狀態文件為準。

## 1. 狀態與規範用語

本文件是所有線上格式的唯一權威來源，版本為 **1.0**，已核准為實作基線；目前 Phase 1 第一批已部分實作，尚非完整 V1 驗收。TCP + JSON Lines + Base64、認證、獨占 TX、世代檢查與不自動重送等原則已由使用者明示；具體欄位、訊框與操作政策已依 Q-19 接受；實作範圍及剩餘工作見 [專案狀態](../status.md)。

「必須／不得」表示此候選契約核准後的要求，不表示使用者已核准所有新增細節。「建議」表示工程選擇。API Method（方法）、JSON Key（欄位名稱）與 Enum（列舉值）均保留英文。其他文件不得另定同名方法的不同格式。

本協定傳輸任意 UART bytes，不把 UART 當作具有請求／回覆邊界的 Shell RPC（殼層遠端呼叫），也不提供跨故障 Exactly Once（恰好一次）保證。

本文的 Server（伺服器）、Client（用戶端）、Channel（邏輯通道）、Binding（綁定）、Stream Epoch（資料流世代）及 Snapshot（快照）沿用架構文件的定義。各節 JSON 範例是獨立契約案例，不能依文件出現順序串成同一連線；實際同一連線仍須遵守遞增 Request ID。

## 2. 基本型別與相容性

以下型別定義適用所有欄位表。所有欄位在 1.0 首次定義；表中的「1.0」代表只能在協商出支援此契約後使用。「可選」欄位的缺省行為必須依表格，不由實作者猜測。

| 型別 | 合法值與語意 |
| --- | --- |
| `Id` | 1–64 個 ASCII 字元，僅 `A-Z a-z 0-9 _ -`；Opaque（不透明）識別，不以內容推論權限 |
| `U64` | 十進位 JSON string，符合 `0\|[1-9][0-9]*` 且值不超過 18446744073709551615；不可用浮點數傳輸 |
| `Size` | JSON integer，0–2147483647；byte 數、毫秒或有限數量依欄位說明；不得使用小數、NaN 或 Infinity |
| `Time` | UTC RFC 3339 字串，固定 `YYYY-MM-DDTHH:mm:ss.sssZ`，有效日期時間；不是 Lease（租約）判斷依據 |
| `Version` | 物件，必要 `major`、`minor` 都是 0–65535 integer；1.0 候選只支援 `{ "major": 1, "minor": 0 }` |
| `Text` | 合法 UTF-8 字串，長度限制以編碼後 bytes 計算；不得含未配對 Unicode surrogate（代理碼） |
| `Binary` | RFC 4648 標準 Base64 字串，含必要 `=` padding（補齊），不得含空白或換行；解碼後受 Payload（負載）上限限制 |

ID 的唯一性範圍：`gateway_instance_id` 每次程序啟動全新；`session_id`、`subscription_id` 在 Instance 內不重用；`channel_id` 為穩定設定 ID；`stream_epoch` 每次新資料流全新。`binding_revision` 與 `fencing_token` 在同 Instance／Channel 內遞增。`tx_id` 由 Client 產生，對同 Principal（認證身分）不得重用，建議使用 UUID（通用唯一識別碼）。

計數器不得溢位後繞回；RX 計數將溢位時終止舊 Epoch 並建立新 Epoch。Revision／Fencing 無法安全增加時拒絕操作，需明確復原，不能沿用舊值。

### 2.1 相容規則

- 套件版本與協定版本分開；Hello 選定後，整條連線使用同一版本。
- Client 提供可支援的確切版本集合，Server 選共同支援的最高 `(major, minor)`；沒有交集即拒絕。
- Minor（次版本）擴充不得改變既有欄位型別、必要性、缺省或副作用語意；破壞性變更使用新 Major（主版本）。
- Request（請求）的未知 Method 回覆 `UNKNOWN_METHOD`；未知參數回覆 `INVALID_PARAMS`，避免拼字錯誤被默默忽略。新增參數必須先協商支援版本／Capability（能力）。
- Response（回覆）及已知 Event（事件）中的未知可選欄位應忽略；缺少必要欄位、型別不符或違反目前版本的不變量是協定錯誤。
- 未協商的未知必要 Event 不得被當作成功；候選 V1 關閉該連線並報告本地協定錯誤。未來可忽略事件須在相應版本明確標成可選。
- 不因看不懂版本而退回 Raw TCP（原始串流）。同一 Port（連接埠）不做協定猜測。

## 3. TCP 與 JSON Lines Framing

每個 Frame（訊框）為單一 JSON object 的 UTF-8 編碼，最後恰有一個 LF byte（`0x0A`）。沒有 BOM（位元組順序標記），不使用 CRLF，不接受空白行或 JSON array 作根物件；字串中的 CR／LF 必須 JSON escape（跳脫）。文件的多行 JSON 範例只是排版，傳送前必須序列化為單行後附 LF。

TCP 不保證一次 read 對應一個 Frame。接收端累積分段、解析每個 LF 結束的 Frame，保留尚未完成的尾端；一次 read 可能包含多個 Frame。

候選硬上限為 **65536 bytes，含 LF**。Server 可設定較小值（至少 16384），並在 Hello 宣告；握手前亦不得超過 65536。接收端在尚未見 LF 時就必須限制累積量；超限停止解析並關閉，不先配置超大記憶體。

拒絕非法 UTF-8、重複 Key（包含巢狀物件）、超過深度限制及非法 JSON 數字。可回覆時送 `INVALID_FRAME` 後關閉；無法可靠取得 ID 時 Error Response（錯誤回覆）的 `id` 為 null。不合法 Base64 屬已解析 Request 的參數錯誤，回覆 `INVALID_PARAMS`，不因此自動關閉連線。不得把原始輸入或 Token（憑證）回顯到錯誤文字。

同一 Connection（連線）僅一個 Writer（輸出工作路徑）序列化完整 Frame；不得讓並行 Task（工作）交錯寫 bytes。輸出 Queue（佇列）有界，控制訊息優先且資料依 Channel 公平排程；已進入 TCP 的 bytes 無法被後來控制訊息超車。

## 4. Connection 與 Session 生命週期

狀態為 `connected → negotiated → authenticated → closing → closed`。

1. TCP 接受後第一個 Request 必須是 `hello`。
2. Hello 成功後只允許 `auth.authenticate`；認證成功才建立 Session（工作階段）。
3. 從 TCP 接受到認證完成共享一個握手期限；建議 5000 ms，不因 Hello 或錯誤重設。
4. 同一連線只協商及認證一次。重複 Hello／Auth 或提前 Authenticate 回覆 `INVALID_STATE` 後關閉；尚未認證即要求一般 API 回覆 `AUTH_REQUIRED` 後關閉。
5. 認證失敗回覆 `AUTH_FAILED` 後關閉；不提供可推論 Token 或 Principal 存在與否的細節。
6. EOF、逾時、協定錯誤或 Server 關閉時集中清理訂閱、Lease 及未開始的 TX。
7. 重連必須重新協商與認證，建立新 Session。V1 沒有 Session Resume（工作階段恢復）Token。

Session 不等於 Principal，也不等於 Channel。一條 Session 可操作被授權的多個 Channel；某個 Channel 故障不應關閉其餘 Channel。

## 5. Message Envelope（訊息外層）

### 5.1 Request

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `type` | string | 必要 | 固定 `request` | 1.0 |
| `id` | U64 | 必要 | 同一連線嚴格遞增、從大於 0 開始；用於 Response 配對，不是 TX ID | 1.0 |
| `method` | string | 必要 | 本文件定義的方法，最多 64 ASCII 字元 | 1.0 |
| `params` | object | 必要 | 即使無參數也傳 `{}`；依方法驗證 | 1.0 |

Server 在派送前檢查 ID 大於該連線前一個 Request ID；重複或倒退回覆 `INVALID_REQUEST_ID` 後關閉。只需保存最大 ID，不能為此建立無限的 ID 集合。Response 可依完成順序返回，不保證與 Request 順序相同。

### 5.2 Response

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `type` | string | 必要 | 固定 `response` | 1.0 |
| `id` | U64 或 null | 必要 | 對應 Request；僅無法解析有效 ID 的連線錯誤可為 null | 1.0 |
| `ok` | boolean | 必要 | 成功為 true，失敗為 false | 1.0 |
| `result` | object | `ok=true` 必要 | 方法專屬結果；不得同時有 `error` | 1.0 |
| `error` | Error object | `ok=false` 必要 | 見第 17 節；不得同時有 `result` | 1.0 |

`ok=true` 只表示 API 呼叫成功，不表示 TX 已物理送達或命令成功。每筆 Request 至多一個 Response，非同步進度使用 Event。

Server 只接受 Request，Client 只接受 Response／Event。方向錯誤、外層必要欄位缺漏、未知外層 Request 欄位或 `params` 不是物件，按 `INVALID_FRAME` 關閉；若可識別為 Request 但 ID 不合法，使用 `INVALID_REQUEST_ID`。方法參數的錯誤則使用 `INVALID_PARAMS`，與外層格式錯誤分開。

### 5.3 Channel Event

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `type` | string | 必要 | 固定 `event` | 1.0 |
| `event` | string | 必要 | `rx/gap/subscription_state/channel_state/lease_revoked/tx_result/recording_state` | 1.0 |
| `channel_id` | Id | 必要 | 事件所屬 Channel | 1.0 |
| `binding_revision` | U64 | 必要 | 該事件所屬綁定修訂 | 1.0 |
| `stream_epoch` | Id 或 null | 必要 | RX／Gap 必須非 null；生命週期事件可能沒有目前資料流 | 1.0 |
| `timestamp_utc` | Time | 必要 | 觀測時間；RX Replay 保留原始觀測時間 | 1.0 |
| `data` | object | 必要 | 事件專屬內容 | 1.0 |

Event 不帶 Request ID；RX 使用 Subscription ID（訂閱識別），TX 使用 TX ID 配對。UTC 時鐘可能校時，不使用它推算順序或到期。

## 6. Hello 與版本協商

`hello.params`：

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `versions` | array[Version] | 必要 | 1–16 個不重複且確切支援的版本 | Bootstrap（初始握手）1 |
| `client_name` | Text | 必要 | 1–64 bytes，僅供診斷 | Bootstrap 1 |
| `client_version` | Text | 必要 | 1–32 bytes，Client 套件版本 | Bootstrap 1 |

Hello 是固定初始握手格式，尚未協商時仍按以上規則解析。

```json
{
  "type": "request",
  "id": "1",
  "method": "hello",
  "params": {
    "versions": [{"major": 1, "minor": 0}],
    "client_name": "uart-cli",
    "client_version": "0.1.0"
  }
}
```

`hello.result`：

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `version` | Version | 必要 | 選定的共同版本 | Bootstrap 1 |
| `gateway_instance_id` | Id | 必要 | 此程序啟動的唯一識別 | Bootstrap 1 |
| `capabilities` | array[string] | 必要 | 支援能力；V1 候選固定含 `rx.replay`、`tx.status`、`binding.confirm`，不可用來繞過 ACL | 1.0 |
| `auth_methods` | array[string] | 必要 | V1 為 `["token"]` | 1.0 |
| `limits` | Limits object | 必要 | 本連線／服務實際限制；見下表 | 1.0 |

Limits 的所有欄位必要，型別為 Size、版本 1.0。合法範圍以 [設定規格](../configuration.md) 對應欄位為準，表中數值僅為候選範例；Server 不得宣告超過本文件硬上限的值。

| 欄位 | 語意 | 候選值 |
| --- | --- | --- |
| `max_frame_bytes` | 含 LF 的 Frame 上限 | 65536 |
| `max_json_depth` | 巢狀容器深度；根物件為 1 | 16 |
| `max_rx_chunk_bytes` | 單次 RX 的解碼 bytes 上限 | 4096 |
| `max_tx_bytes` | 單次 TX 的解碼 bytes 上限 | 4096 |
| `max_pending_requests` | 每 Session 未回覆 Request 上限 | 32 |
| `max_subscriptions` | 每 Session 訂閱上限 | 16 |
| `max_channel_list_items` | 一頁最多項目，V1 固定合法範圍 1–16 | 16 |
| `rx_ring_bytes` | 每 Channel Ring（環狀緩衝）容量 | 4194304 |
| `max_tx_queue_items` | 每 Channel 等待 TX 的筆數，不含執行中項目 | 16 |
| `max_tx_queue_bytes` | 每 Channel 等待 TX 的 bytes | 65536 |
| `handshake_timeout_ms` | 自 TCP 接受起的總期限，不會重新開始 | 5000 |
| `heartbeat_interval_ms` | 建議 Ping 間隔 | 5000 |
| `idle_timeout_ms` | 無有效入站訊息的關閉期限 | 15000 |
| `lease_ttl_ms` | Server 使用的 Lease 有效期間 | 15000 |
| `lease_renew_interval_ms` | SDK 建議更新間隔 | 5000 |
| `tx_result_retention_ms` | TX 最終結果最少保留期間 | 600000 |
| `tx_result_cache_entries` | Instance 內 TX 紀錄總上限 | 4096 |

```json
{
  "type": "response",
  "id": "1",
  "ok": true,
  "result": {
    "version": {"major": 1, "minor": 0},
    "gateway_instance_id": "g_01",
    "capabilities": ["rx.replay", "tx.status", "binding.confirm"],
    "auth_methods": ["token"],
    "limits": {
      "max_frame_bytes": 65536,
      "max_json_depth": 16,
      "max_rx_chunk_bytes": 4096,
      "max_tx_bytes": 4096,
      "max_pending_requests": 32,
      "max_subscriptions": 16,
      "max_channel_list_items": 16,
      "rx_ring_bytes": 4194304,
      "max_tx_queue_items": 16,
      "max_tx_queue_bytes": 65536,
      "handshake_timeout_ms": 5000,
      "heartbeat_interval_ms": 5000,
      "idle_timeout_ms": 15000,
      "lease_ttl_ms": 15000,
      "lease_renew_interval_ms": 5000,
```

## 7. Authentication 與 Channel Authorization

`auth.authenticate.params`：

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `scheme` | string | 必要 | 固定 `token` | 1.0 |
| `token` | string | 必要 | 43–128 ASCII Base64url 字元、不含 padding；需對應受保護設定 | 1.0 |

候選認證資料由至少 32 bytes 隨機值產生；長度驗證不等於熵保證。下例是無效的示範憑證，不得配置為真實 Token。

```json
{
  "type": "request",
  "id": "2",
  "method": "auth.authenticate",
  "params": {
    "scheme": "token",
    "token": "example_only_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  }
}
```

`auth.authenticate.result`：

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `session_id` | Id | 必要 | 新建的連線工作階段 | 1.0 |
| `principal_id` | Id | 必要 | Server 從憑證判定的身分 | 1.0 |
| `grants` | array[Grant] | 必要 | 僅列出該身分授權；空陣列表示無可存取 Channel | 1.0 |
| `Grant.channel_id` | Id | 必要 | 授權通道 | 1.0 |
| `Grant.permissions` | array[string] | 必要 | 不重複的 `read/tx/configure` 集合；`tx`、`configure` 需有 `read` | 1.0 |

```json
{
  "type": "response",
  "id": "2",
  "ok": true,
  "result": {
    "session_id": "s_01",
    "principal_id": "operator_01",
    "grants": [
      {"channel_id": "ch_lab_1", "permissions": ["read", "tx", "configure"]}
    ]
  }
}
```

Session 身分由 Connection 綁定，後續 Request 不允許自填 Session 或 Principal 來切換權限。`read` 允許查詢與訂閱；`tx` 允許取得 Lease／送出／查詢自己的 TX；`configure` 允許 Binding 操作。V1 不提供查詢他人 TX 或強制搶占。

## 8. Channel API 與 Snapshot（快照）

`channel.list` 回覆該 Principal 可讀的 Channel。`channel.get` 回覆單一 Snapshot，不洩漏無權限通道的詳細狀態。

| 方法／欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `channel.list.params.limit` | Size | 可選 | 1 至 `max_channel_list_items`；缺省為該上限 | 1.0 |
| `channel.list.params.cursor` | Text 或 null | 可選 | 缺省 null；Server 給出的不透明游標，最多 256 bytes | 1.0 |
| `channel.list.result.channels` | array[ChannelSnapshot] | 必要 | 本頁結果，可為空 | 1.0 |
| `channel.list.result.next_cursor` | Text 或 null | 必要 | 同 Session 下一頁；null 表示結束 | 1.0 |
| `channel.get.params.channel_id` | Id | 必要 | 要查詢的通道 | 1.0 |
| `channel.get.result.channel` | ChannelSnapshot | 必要 | 目前快照 | 1.0 |

清單以 Channel ID 排序，初始請求固定本次列舉的 ID 集合；每個 Snapshot 為回覆時狀態，不承諾跨頁原子快照。Server 依 Frame 上限縮小頁面，不截斷 JSON。每個 Session 只保留一個有界列舉 Cursor；新列舉替換舊 Cursor。Cursor 失效回覆 `INVALID_CURSOR`，Client 重新列舉。

| `target_note` | Text 或 null | 最多 512 bytes，人工目標描述 | 1.0 |
| `state` | string | `closed/opening/ready/draining/lost/faulted` | 1.0 |
| `binding` | object | 下列綁定欄位 | 1.0 |
| `binding.revision` | U64 | 同 Instance／Channel 的修訂 | 1.0 |
| `binding.status` | string | `unconfirmed/rebinding/confirmed` | 1.0 |
| `stream_epoch` | Id 或 null | 目前資料流，沒有時為 null | 1.0 |
| `adapter` | object | 下列觀測裝置資訊 | 1.0 |

| `serial.stopbits` | number | 1、1.5、2 | 1.0 |
| `serial.flow_control` | string | `none/rtscts/xonxoff` | 1.0 |
| `serial.dtr`／`serial.rts` | boolean | 設定意圖，不保證開啟瞬間無脈衝 | 1.0 |
| `serial.read_timeout_ms`／`serial.write_timeout_ms` | Size | 合法範圍見設定；有限等待 | 1.0 |
| `serial_source` | string | `configured` 為預定設定；`applied` 為 Backend 已套用回報，不代表硬體量測 | 1.0 |
| `rx` | object | 下列 RX 範圍 | 1.0 |
| `rx.earliest_offset`／`rx.next_offset` | U64 或 null | 有 Epoch 時為最早可用位置與目前尾端；無 Epoch 時均為 null | 1.0 |
| `tx` | object | 下列操作權狀態 | 1.0 |
| `tx.state` | string | `idle/leased/quiescing/blocked` | 1.0 |
| `tx.owner_session_id` | Id 或 null | 目前 Owner，無 Lease 時 null | 1.0 |
| `recording` | object | 下列錄製健康度 | 1.0 |
| `recording.state` | string | `disabled/recording/degraded/failed` | 1.0 |
| `recording.integrity` | string | `not_recording/no_known_gap/incomplete/unknown` | 1.0 |
| `last_error` | object 或 null | 最近 Channel 錯誤，不含秘密 | 1.0 |
| `last_error.code` | string | 非 null 時必要，使用第 17 節錯誤碼 | 1.0 |
| `last_error.message` | Text | 非 null 時必要，最多 512 bytes，供人閱讀 | 1.0 |

`earliest_offset <= next_offset`；Ring 為空時兩者相同。內部已知缺口不改成連續資料，需按第 12 節處理。`no_known_gap` 只表示對已觀測資料沒有已知錄製缺口，不證明 UART 前段零遺失。

Label 在已設定 Channel 集合中以完整 Unicode 字串精確比對，區分大小寫；V1 不做隱含正規化或別名比對。所有實際操作仍使用 Channel ID。

```json
  "id": "3",
  "method": "channel.list",

}
```


## 9. Expected Context 與 Binding API

所有 Binding／Lease／TX 寫入方法使用 `expected`，避免 Client 依舊畫面操作新板子。

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `expected.gateway_instance_id` | Id | 必要 | 必須等於目前 Instance | 1.0 |
| `expected.binding_revision` | U64 | 必要 | 必須等於目前 Binding Revision | 1.0 |
| `expected.stream_epoch` | Id 或 null | 必要 | 必須等於目前 Epoch；Lease／TX 必須非 null，Binding 可在 closed 使用 null | 1.0 |

依序檢查認證／ACL、Instance、Channel、Revision、Epoch，再檢查方法專屬狀態；錯誤為 `INSTANCE_MISMATCH`、`CHANNEL_NOT_FOUND`、`STALE_BINDING`、`EPOCH_MISMATCH` 等。TX 已存在紀錄的去重路徑另見第 15 節。

| 方法／欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `binding.rebind.params.channel_id` | Id | 必要 | 需要 `configure` 權限 | 1.0 |
| `binding.rebind.params.expected` | Expected Context | 必要 | 預期目前狀態 | 1.0 |
| `binding.rebind.result.channel` | ChannelSnapshot | 必要 | 成功時 closed、unconfirmed、無 Epoch、Revision 已增加 | 1.0 |
| `binding.confirm.params.channel_id` | Id | 必要 | 需要 `configure` 權限 | 1.0 |
| `binding.confirm.params.expected` | Expected Context | 必要 | 預期目前未確認狀態 | 1.0 |
| `binding.confirm.params.label` | Text | 必要 | 1–128 bytes，與其他有效 Channel 不重名 | 1.0 |
| `binding.confirm.params.target_note` | Text 或 null | 可選 | 缺省 null，最多 512 bytes | 1.0 |
| `binding.confirm.result.channel` | ChannelSnapshot | 必要 | 成功時 ready、confirmed、Revision 已增加且新 Epoch | 1.0 |

`rebind` 不搶占現有 Lease：有 Owner 回覆 `LEASE_BUSY`；有未收斂 Writer 或其他進行中的生命週期操作回覆 `CHANNEL_BUSY`。確認可執行後立即使舊 TX 資格失效、Revision 加一、Binding 轉 rebinding，終止舊訂閱，協調關閉；成功後 closed／unconfirmed。若關閉失敗，Revision 不回退，Channel 轉 faulted、Binding 為 unconfirmed、目前 Epoch 為 null，維持無 TX 資格並回覆 `SERIAL_IO_FAILED`；Client 必須重新 `channel.get`。底層 Handle 尚未收斂時，後續 Rebind／Confirm 仍回 `CHANNEL_BUSY`。

`confirm` 只接受 unconfirmed 且沒有執行中 TX 的 Channel。已 confirmed 時回覆 `INVALID_STATE` 並保留連線；opening／draining 或另一生命週期操作未完成時回覆 `CHANNEL_BUSY`。先檢查 Label／參數與裝置；需要時開啟端點。只有成功後才把新 Metadata（中繼資料）與確認資格一併提交、Revision 加一、建立新 Epoch。已開啟的唯讀 Handle（控制代碼）可保留，但建立新的邏輯 Epoch 並終止舊訂閱。失敗不標成 confirmed，不授予 Lease；狀態或 Epoch 可能因開啟失敗而改變，重新查詢快照。

候選操作的等待上限由 `gateway.lifecycle_timeout_ms` 控制，建議 10000 ms；超時回覆 `SERIAL_IO_FAILED`，Channel 保持無 TX 資格。這不代表底層開關一定停止：晚到的完成回報不得替過期操作確認 Binding，未收斂 Handle 不得交給新 Worker。Client 對 Rebind／Confirm 的本地 Timeout 只能先查快照，不自動重送有副作用請求。

### 9.1 修訂與世代轉移表

| 觸發 | Revision／確認狀態 | Epoch／訂閱／TX |
| --- | --- | --- |
| 程序啟動 | 新 Instance 內 Revision 從 1、unconfirmed | closed 時 null；沒有舊 Session／Lease |
| 自動開啟 RX 成功 | Revision 不變，維持 unconfirmed | 新 Epoch，Offset／seq 從 0；不可 TX |
| Rebind 接受 | Revision 加一，rebinding；完成後 unconfirmed | 停止舊 Epoch 並終止其訂閱；關閉完成後 null；拒絕舊 TX |
| Confirm 成功 | Revision 加一，confirmed | 新 Epoch；舊訂閱終止；可重新取得 Lease |
| 已開啟裝置遺失 | Revision 加一，unconfirmed | 舊 Epoch 結束，目前 Epoch 為 null；撤銷 Lease、取消待送 TX |
| 僅 RX 連續性未知 | 目標未變則 Revision／確認狀態不變 | 結束舊 Epoch；可開始新 Epoch；撤銷舊 Lease、取消待送 TX，通知 Client |
| TX I/O 結果不明 | Revision／確認狀態不自動改變 | TX blocked，撤銷 Lease；RX 可持續；後續人工 Rebind／Confirm 另建世代 |
| 重新開啟遺失裝置 | 維持 unconfirmed，不自動增加確認資格 | 新 Epoch；TX 仍需 Confirm |

同一故障的重複通知不得反覆遞增 Revision。日後 UART 設定變更必須撤銷確認及舊 Lease、建立新 Epoch；V1 沒有該遠端 API。若故障讓目前 Epoch 或可寫狀態無法可靠判斷，停止 TX 並標示 faulted，不猜測成功。

```json
{
  "type": "request",
  "id": "20",
  "method": "binding.rebind",
  "params": {
    "channel_id": "ch_lab_1",
    "expected": {"gateway_instance_id": "g_01", "binding_revision": "7", "stream_epoch": "e_01"}
  }
}
```

下例假定 Rebind 已成功且目前 Revision 為 8；範例不是已執行的操作。

```json
{
  "type": "request",
  "id": "21",
  "method": "binding.confirm",
  "params": {
    "channel_id": "ch_lab_1",
    "expected": {"gateway_instance_id": "g_01", "binding_revision": "8", "stream_epoch": null},
    "label": "R150_new",
    "target_note": "換接完成並人工確認"
  }
}
```

V1 不提供獨立 Rename（改名）、遠端 Adapter Selector（裝置條件）修改、Open／Close／UART Configure 或強制接管 API。換板前仍需確認物理輸出已停止；關閉 Handle 不是硬體 FIFO（先進先出緩衝）清空保證。

## 10. RX Subscription 與 Replay

`rx.subscribe` 需要 `read` 權限及 ready Channel。`mode=live` 從訂閱建立時的尾端開始；`mode=resume` 必須指定 Epoch 與 Offset。每個訂閱只有一個 Epoch。

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `params.channel_id` | Id | 必要 | 通道 | 1.0 |
| `params.mode` | string | 必要 | `live/resume` | 1.0 |
| `params.stream_epoch` | Id | resume 必要、live 不得提供 | 要恢復的世代 | 1.0 |
| `params.from_offset` | U64 | resume 必要、live 不得提供 | 第一個期望的 RX byte 位置 | 1.0 |
| `params.gap_policy` | string | 可選 | `error/skip`，缺省 `error`；live 只能省略或 error | 1.0 |
| `result.subscription_id` | Id | 必要 | 新訂閱 | 1.0 |
| `result.channel_id` | Id | 必要 | 通道 | 1.0 |
| `result.binding_revision` | U64 | 必要 | 訂閱建立時的綁定 | 1.0 |
| `result.stream_epoch` | Id | 必要 | 該訂閱唯一世代 | 1.0 |
| `result.start_offset` | U64 | 必要 | 決定開始傳送的位置，遇 skip 可大於請求位置 | 1.0 |
| `result.replay_until_offset` | U64 | 必要 | 原子擷取的尾端邊界，不包含此 byte | 1.0 |
| `result.earliest_offset` | U64 | 必要 | 建立時最早仍可讀的位置 | 1.0 |

建立訂閱時原子記下 Replay 邊界並接上後續 Live（即時）Queue。先排入 Response，才可輸出該訂閱的 Gap／RX。`start_offset` 至 `replay_until_offset` 之前標為 replay，之後標為 live；每個訂閱的 Offset 依序傳送，不交錯不同訂閱的 Cursor。

Epoch 不符回覆 `EPOCH_MISMATCH`，不建立訂閱；要求超過尾端回覆 `OFFSET_OUT_OF_RANGE`。歷史不足或請求範圍含已知缺口時，預設回覆 `HISTORY_GAP`，不偷偷跳過。只有顯式 `gap_policy=skip` 才可建立訂閱並先發出對應 Gap Event。

```json
{
  "type": "request",
  "id": "4",
  "method": "rx.subscribe",
  "params": {
    "channel_id": "ch_lab_1",
    "mode": "resume",
    "stream_epoch": "e_01",
    "from_offset": "4096",
    "gap_policy": "error"
  }
}
```

```json
{
  "type": "response",
  "id": "4",
  "ok": true,
  "result": {
    "subscription_id": "sub_01",
    "channel_id": "ch_lab_1",
    "binding_revision": "7",
    "stream_epoch": "e_01",
    "start_offset": "4096",
    "replay_until_offset": "4101",
    "earliest_offset": "0"
  }
}
```

Replay 不能無限釘住 Ring 項目。建立時若能在既有有界配額內保留需要的資料即可保留；後續淘汰或 Live Queue 超限則依 Gap 政策終止或明示跳過。預設 error 訂閱在執行途中遇缺口時必須終止，不能改成 skip。用戶端自行過濾、文字顯示或寫檔速度也必須有界。

`rx.unsubscribe.params` 必要 `subscription_id: Id`；`result` 必要 `unsubscribed: boolean`。只作用於目前 Session；存在時 true，不存在或已結束時 false，皆不洩漏其他 Session 資訊。Response 之後不得再輸出該訂閱的 RX；已在輸出順序之前的 Frame 不可撤回。主動取消不另發 ended Event。

## 11. Sequence、Offset、Stream Epoch 與 RX Event

每個 Epoch 的 `offset` 從 0 開始，計算 Gateway 已觀測的原始 RX bytes。`seq` 從 0 開始計算觀測到的 RX Chunk（區塊），不包含狀態事件；這是對原審查事件序號的候選細化，仍需 Q-19 核准。

Gateway 已知丟棄多少 bytes 時仍保留該範圍的 Offset 缺口，不能讓後面的資料向前補位。無法可靠知道遺失範圍時，連續性未知並結束該 Epoch；UART／USB／Driver 在 Gateway 觀測之前的未回報遺失仍可能無法偵測。

`rx.data` 全部欄位必要：

| 欄位 | 型別 | 語意／合法值 | 版本 |
| --- | --- | --- | --- |
| `subscription_id` | Id | 所屬訂閱 | 1.0 |
| `seq` | U64 | 原始 RX Chunk 序號，Replay 不重編 | 1.0 |
| `chunk_offset` | U64 | 原始 Chunk 起點 | 1.0 |
| `offset` | U64 | 本 Frame 第一個 byte 位置，至少為 chunk_offset | 1.0 |
| `next_offset` | U64 | `offset + Base64 解碼長度`，不包含此位置 | 1.0 |
| `delivery` | string | `replay/live` | 1.0 |
| `data_b64` | Binary | 解碼後 1 至 max_rx_chunk_bytes；不可空 Payload | 1.0 |

Resume 從 Chunk 中間開始時，只傳該 Chunk 後半，保留原始 `seq`、`chunk_offset` 與 Timestamp。完整性依 Offset 與 Gap 判讀，不以 seq 跳號單獨宣稱漏掉多少 bytes。

```json
{
  "type": "event",
  "event": "rx",
  "channel_id": "ch_lab_1",
  "binding_revision": "7",
  "stream_epoch": "e_01",
  "timestamp_utc": "2026-11-02T07:00:00.123Z",
  "data": {
    "subscription_id": "sub_01",
    "seq": "118",
    "chunk_offset": "4096",
    "offset": "4096",
    "next_offset": "4101",
    "delivery": "replay",
    "data_b64": "Ym9vdAo="
  }
}
```

此 Payload 為 `boot` 後接 LF，共 5 bytes。Client 的續讀 Cursor（位置）為 `(gateway_instance_id, channel_id, stream_epoch, next_offset)`；只有在所需處理／儲存完成後才前移，避免先更新 Cursor 卻尚未保存資料。

## 12. Gap Handling 與訂閱終止

`gap.data` 全部欄位必要：

| 欄位 | 型別 | 語意／合法值 | 版本 |
| --- | --- | --- | --- |
| `subscription_id` | Id | 受影響訂閱 | 1.0 |
| `reason` | string | `history_evicted/rx_handoff_overflow/subscriber_overflow/continuity_unknown` | 1.0 |
| `from_offset` | U64 或 null | 已知缺口起點；未知時 null | 1.0 |
| `to_offset` | U64 或 null | 缺口尾端，不包含此位置；已知時大於 from_offset | 1.0 |
| `continuity` | string | `known_gap/unknown`；unknown 時兩個 Offset 都 null | 1.0 |
| `action` | string | `skip/terminate`；只有顯式 skip 訂閱可 skip 已知缺口 | 1.0 |

```json
{
  "type": "event",
  "event": "gap",
  "channel_id": "ch_lab_1",
  "binding_revision": "7",
  "stream_epoch": "e_01",
  "timestamp_utc": "2026-11-02T07:01:00.000Z",
  "data": {
    "subscription_id": "sub_gap_01",
    "reason": "history_evicted",
    "from_offset": "1024",
    "to_offset": "4096",
    "continuity": "known_gap",
    "action": "skip"
  }
}
```

此例屬另一個明確使用 skip 的訂閱；不套用到前例 gap_policy=error 的 `sub_01`。缺口不放進 `data_b64` 假裝為 UART 字串。

慢 Client 超過 Subscription Queue 時先停止該訂閱，盡可能送 Gap 與 ended；若 Connection Queue 也無法輸出控制訊息，關閉連線並記錄原因，不保證最後通知能送達。Client 重連仍以最後完成的 Cursor 判斷缺口。已知範圍只表示 Server 確認未交付的區間，不是 TCP 接收確認。

`subscription_state.data` 的必要欄位：`subscription_id: Id`、`state: string`（固定 `ended`）、`reason: string`（`epoch_changed/device_lost/slow_consumer/history_gap/channel_closed/server_shutdown`）。全部為 1.0。舊 Epoch 終止後不得以相同 Subscription ID 發送新 Epoch RX；Session 可繼續，Client 明確建立新訂閱。

對連續性未知的 Gap 一律 terminate；已知缺口的 Metadata（中繼資料）也需有界，無法保留時不能繼續宣稱範圍精確。

## 13. Lease Acquire／Renew／Release 與 Fencing

每 Channel 同時最多一個 Lease Owner，綁定 Principal、Session、Channel、Revision 與 Epoch。Lease 到期依 Server Monotonic Clock（單調時鐘）判斷，`now >= deadline` 即失效。Client 不可用本機 UTC 時間認定仍有權限。

| 方法／欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| 三方法 `params.channel_id` | Id | 必要 | 需要 tx 權限 | 1.0 |
| 三方法 `params.expected` | Expected Context | 必要 | Epoch 必須非 null 且符合目前狀態 | 1.0 |
| `lease.renew/release.params.fencing_token` | U64 | 必要 | 目前 Session 所持有且未失效的隔離序號 | 1.0 |
| `lease.acquire/renew.result.channel_id` | Id | 必要 | 所屬 Channel | 1.0 |
| `lease.acquire/renew.result.fencing_token` | U64 | 必要 | 同 Instance／Channel 每次新授權遞增 | 1.0 |
| `lease.acquire/renew.result.ttl_ms` | Size | 必要 | Server 有效期間設定 | 1.0 |
| `lease.acquire/renew.result.remaining_ms` | Size | 必要 | 回覆形成時的剩餘期間，0 至 ttl_ms | 1.0 |
| `lease.release.result.released` | boolean | 必要 | 成功為 true | 1.0 |
| `lease.release.result.tx_state` | string | 必要 | `idle/quiescing/blocked` | 1.0 |

Acquire 需 ready、confirmed、TX 可接受且沒有其他 Owner。同 Session 再次 Acquire 回傳原 Token 與剩餘期間，不延長；Renew 才設為 `now + ttl`。其他 Owner 持有時 `LEASE_BUSY`；尚有未收斂寫入時 `CHANNEL_BUSY`；結果不明被封鎖時 `TX_BLOCKED`。

```json
{
  "type": "request",
  "id": "5",
  "method": "lease.acquire",
  "params": {
    "channel_id": "ch_lab_1",
    "expected": {"gateway_instance_id": "g_01", "binding_revision": "7", "stream_epoch": "e_01"}
  }
}
```

```json
{
  "type": "response",
  "id": "5",
  "ok": true,
  "result": {"channel_id": "ch_lab_1", "fencing_token": "12", "ttl_ms": 15000, "remaining_ms": 15000}
}
```

```json
{
  "type": "request",
  "id": "6",
  "method": "lease.renew",
  "params": {
    "channel_id": "ch_lab_1",
    "expected": {"gateway_instance_id": "g_01", "binding_revision": "7", "stream_epoch": "e_01"},
    "fencing_token": "12"
  }
}
```

```json
{
  "type": "response",
  "id": "6",
  "ok": true,
  "result": {"channel_id": "ch_lab_1", "fencing_token": "12", "ttl_ms": 15000, "remaining_ms": 15000}
}
```

Release、到期、Session 結束或裝置／Binding 改變時，撤銷 Token 並取消尚未開始的 TX。Release 已不存在的 Lease 回覆 `LEASE_EXPIRED`，不建立新 Owner。已開始的 I/O 需要先收斂，新 Owner 不得與它並行寫入；到期不代表物理 bytes 能撤回。

Fencing Token 不是秘密或認證憑證。Server 必須同時驗證 Session／Principal、Channel、Expected Context 與有效 Token；只比對一個整數不構成授權。

## 14. TX Request 與結果狀態

`tx.write` 只傳 bytes，不補換行、不解讀字串、不以內容判斷命令成功，也不自動切分大型命令。

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `params.channel_id` | Id | 必要 | 需要 tx 權限 | 1.0 |
| `params.expected` | Expected Context | 必要 | 必須為目前 Instance／Revision／非 null Epoch | 1.0 |
| `params.fencing_token` | U64 | 必要 | 目前 Session 的有效隔離序號 | 1.0 |
| `params.tx_id` | Id | 必要 | 此操作唯一 ID，不同於 Request ID | 1.0 |
| `params.data_b64` | Binary | 必要 | 解碼後 1 至 max_tx_bytes | 1.0 |
| `result.tx` | TxResult | 必要 | 首次接受固定先回 pending；重複已知操作可回快取狀態 | 1.0 |

第一次接受前驗證權限、Context、Lease、Payload 與 Queue／結果快取容量；預留結果紀錄與 Queue 槽後才承諾 pending。未接受的請求回 Error Response，保證沒有因此開始 I/O，但不建立 TX 紀錄；日後查不到紀錄不能反向推論當時未執行。

接受後先將 pending Response 排入同連線輸出，再允許該操作的最終 Event 輸出。Serial Dispatch（真正開始寫入）前再次驗證 Lease、Binding、Epoch，並與撤銷／生命週期共用同步邊界。不能只在入列時檢查。

```json
{
  "type": "request",
  "id": "7",
  "method": "tx.write",
  "params": {
    "channel_id": "ch_lab_1",
    "expected": {"gateway_instance_id": "g_01", "binding_revision": "7", "stream_epoch": "e_01"},
    "fencing_token": "12",
    "tx_id": "tx_01",
    "data_b64": "dW5hbWUgLWEK"
  }
}
```

範例為 `uname -a` 後接 LF，共 9 bytes；是否可在該板子送出由使用者工作流程決定，Gateway 不把此內容當作授權。

### 14.1 TxResult 欄位

所有欄位必要，版本均為 1.0。

| 欄位 | 型別 | 語意／合法值 |
| --- | --- | --- |
| `tx_id` | Id | 操作識別 |
| `channel_id` | Id | 操作目標 |
| `gateway_instance_id` | Id | 此操作原本指定的 Instance；查詢舊 Instance 時仍回原值 |
| `state` | string | `rejected/pending/written_to_driver/unknown` |
| `submitted_bytes` | Size 或 null | 已知時為原始 Payload 長度；找不到紀錄時 null |
| `accepted_bytes` | Size 或 null | Driver 可可靠回報的接受量；不是物理送達量；不確定則 null |
| `io_started` | boolean 或 null | 是否已開始 I/O；找不到紀錄時 null |
| `reason_code` | string 或 null | 下表原因；成功／pending 可為 null |
| `completed_at` | Time 或 null | 最終狀態形成時間；pending 或無紀錄時 null |
| `retained_for_ms` | Size 或 null | 最終紀錄剩餘最少保留期間；pending 為 null，無紀錄為 0 |
| `status_origin` | string | `record` 為已知紀錄，`unavailable` 為無可用紀錄 |

| 狀態 | 嚴格語意與欄位限制 |
| --- | --- |
| `pending` | 已接受，排隊或 I/O 進行中；accepted_bytes=null；io_started 為目前是否開始；completed_at=null |
| `rejected` | 已接受後在 I/O 開始前被取消／拒絕；io_started=false、accepted_bytes=0；有完成時間 |
| `written_to_driver` | Driver 明確接受全部 bytes；io_started=true、accepted_bytes=submitted_bytes；不代表 Shell 執行成功 |
| `unknown` 且 origin=record | I/O 曾開始但最終接受量／後續效果無法可靠確定；可能部分或全部已送出；accepted_bytes 只在可靠時填值 |
| `unknown` 且 origin=unavailable | 紀錄過期、Server 重啟或根本沒有可用紀錄；submitted_bytes、accepted_bytes、io_started、completed_at 均 null |

`reason_code` 候選集合：`LEASE_EXPIRED`、`LEASE_RELEASED`、`SESSION_CLOSED`、`STALE_BINDING`、`EPOCH_MISMATCH`、`DEVICE_MISSING`、`SERVER_SHUTDOWN`（I/O 前拒絕）；`SERIAL_WRITE_FAILED`、`SERIAL_WRITE_TIMEOUT`、`PARTIAL_WRITE`、`CHANNEL_LOST`（I/O 後不確定）；`RESULT_UNAVAILABLE`、`SERVER_RESTARTED`（無紀錄）。它們是 TX 原因，不全是 Error Response 碼。

```json
{
  "type": "response",
  "id": "7",
  "ok": true,
  "result": {
    "tx": {
      "tx_id": "tx_01", "channel_id": "ch_lab_1", "gateway_instance_id": "g_01",
      "state": "pending", "submitted_bytes": 9, "accepted_bytes": null,
      "io_started": false, "reason_code": null, "completed_at": null,
      "retained_for_ms": null, "status_origin": "record"
    }
  }
}
```

最終結果以 `tx_result` Event 傳給原 Session（若仍存活），`data.tx` 為必要 TxResult，版本 1.0：

```json
{
  "type": "event",
  "event": "tx_result",
  "channel_id": "ch_lab_1",
  "binding_revision": "7",
  "stream_epoch": "e_01",
  "timestamp_utc": "2026-11-02T07:02:00.000Z",
  "data": {
    "tx": {
      "tx_id": "tx_01", "channel_id": "ch_lab_1", "gateway_instance_id": "g_01",
      "state": "written_to_driver", "submitted_bytes": 9, "accepted_bytes": 9,
      "io_started": true, "reason_code": null, "completed_at": "2026-11-02T07:02:00.000Z",
      "retained_for_ms": 600000, "status_origin": "record"
    }
  }
}
```

每個已接受 TX 最多轉成一個最終狀態；不能在 unknown 後自動重做來改成成功。部分寫入或 I/O 逾時候選一律將 Channel TX 轉 blocked、撤銷 Lease；人工確認及有界收斂後才可 Rebind／Confirm。單純查詢得到 origin=unavailable 的 unknown 不改變 Channel 狀態。若執行緒仍卡住，不能透過另一個 Writer 繼續操作，可能需要明確的程序復原。

## 15. TX ID、結果查詢與去重界線

結果快取 Key（索引）為 `(gateway_instance_id, principal_id, tx_id)`。Fingerprint（內容指紋）包括 Channel、Expected Instance／Revision／Epoch 與原始 Payload；Request ID、Session ID 與 Fencing Token 不屬內容指紋。

已通過目前身分及 Channel tx 權限檢查後，若 Key 存在且 Fingerprint 相同，直接返回既有 TxResult，不再寫入，也不要求舊 Lease 仍有效；不同則 `TX_ID_CONFLICT`。這是防禦性去重，**不允許 Client 因 Timeout 自動重送**。

接受前預留結果槽；pending 紀錄不可淘汰。進入最終狀態後，至少保留 Hello 宣告期間。容量滿且沒有已過期紀錄時回 `RESULT_CACHE_FULL`，不提前淘汰仍在保證期間內的紀錄。過期後不提供永久去重；Client 不得重用或重送舊 TX ID。

| `tx.status` 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |
| --- | --- | --- | --- | --- |
| `params.channel_id` | Id | 必要 | 需目前 tx 權限 | 1.0 |
| `params.gateway_instance_id` | Id | 必要 | 原操作 Instance | 1.0 |
| `params.tx_id` | Id | 必要 | 查詢同 Principal 的操作 | 1.0 |
| `result.tx` | TxResult | 必要 | 現有狀態，或 origin=unavailable 的 unknown | 1.0 |

重連後同 Principal 可查舊 Session 的結果；不能查另一身分。不同 Instance 回 unknown／SERVER_RESTARTED；同 Instance 無紀錄回 unknown／RESULT_UNAVAILABLE。不得回 rejected 來表示「查不到」。

```json
{
  "type": "request",
  "id": "8",
  "method": "tx.status",
  "params": {"channel_id": "ch_lab_1", "gateway_instance_id": "g_01", "tx_id": "tx_missing"}
}
```

```json
{
  "type": "response",
  "id": "8",
  "ok": true,
  "result": {
    "tx": {
      "tx_id": "tx_missing", "channel_id": "ch_lab_1", "gateway_instance_id": "g_01",
      "state": "unknown", "submitted_bytes": null, "accepted_bytes": null,
      "io_started": null, "reason_code": "RESULT_UNAVAILABLE", "completed_at": null,
      "retained_for_ms": 0, "status_origin": "unavailable"
    }
  }
}
```

網路逾時可能發生在接受前、寫入中或 Response 遺失後。Client 本地 Timeout 不是 Server 取消命令。可查詢狀態，但無法查到結果時必須回報不確定，不能自動建立新 TX ID 補送相同命令。

## 16. 其他事件與 Heartbeat

以下資料欄位都屬 1.0 且必要，除明示 nullable 外不得省略。

| Event／欄位 | 型別 | 語意／合法值 |
| --- | --- | --- |
| `channel_state.data.channel` | ChannelSnapshot | 變更後狀態；外層 Revision／Epoch 對應此 Snapshot |
| `lease_revoked.data.fencing_token` | U64 | 被撤銷的 Token |
| `lease_revoked.data.reason` | string | `released/expired/session_closed/device_lost/rebind/epoch_changed/tx_unknown/server_shutdown` |
| `recording_state.data.state` | string | `disabled/recording/degraded/failed` |
| `recording_state.data.integrity` | string | `not_recording/no_known_gap/incomplete/unknown` |
| `recording_state.data.reason_code` | string 或 null | null、`RECORDING_IO_FAILED`、`RECORDING_OVERFLOW`、`UNCLEAN_SHUTDOWN`；此處為錄製原因 |

Channel／Recording 事件一般送給該通道的有效訂閱者及 Lease Owner；Lease 撤銷事件送原 Owner（若可達），並記入 Audit（稽核）。生命週期變更先擷取受影響 Session 集合；即使因此移除訂閱或 Lease，仍向該集合排入舊訂閱終止通知，再排入新 Channel 狀態，不能因先清理資源而漏通知。不得讓舊訂閱收取新 Epoch RX。此後未持有資源的 Client 以有界退避的 `channel.get` 查詢是否可重新訂閱，不另建泛用事件匯流排。

`ping.params` 為 `{}`，需已認證；`ping.result` 必要 `server_time_utc: Time`，版本 1.0。此 Response 即 Pong（存活回覆），不另有 `pong` Method。SDK 獨立於畫面與慢 Callback（回呼）定期 Ping；所有有效認證後入站 Request 都可更新 Server 的最近活動時間，但亂碼或未完成 Frame 不延長期限。

Server 向 Client 持續送 RX 不代表 Client 仍能控制連線。若超過 idle_timeout_ms 沒有有效入站訊息，關閉並清理；SDK 若在期限內沒有收到預期 Ping Response，同樣將連線判定失效。Heartbeat 不延長 Lease，只有成功 Renew 才延長。

Error object：

| 欄位 | 型別 | 必要性 | 語意／合法值 | 版本 |

| `code` | string | 必要 | 下表穩定錯誤碼 | 1.0 |
| `message` | Text | 必要 | 最多 512 bytes，供人閱讀；Client 不解析文字決策 | 1.0 |
| `details` | object | 必要 | 可為空；只使用下列可選欄位 | 1.0 |

Details 可選欄位全部屬 1.0：

| 欄位 | 型別／合法值 | 用途 |

## 18. Timeout、Queue 與 Payload Limits

設定候選值與合法範圍見 [設定文件](../configuration.md)，Hello 回報實際值。所有限制包含建立新 Session／訂閱／TX 前的容量驗證，不在耗盡資源後才發現。

- UART Read Timeout 是正常空讀取；Write Timeout 可能已送出部分資料，不能直接回 rejected。
- 每 Channel 的 Reader 交接、Ring、Subscription、TX Queue，以及每 Connection 的輸出與 Recorder Queue 都有界；Metadata 與引用物件也需計入。
- 每條連線公平排程各 Channel 的資料，為 Response／Heartbeat 保留空間；總輸出仍超限時關閉慢連線，不能停住 UART Reader。
- Base64 解碼前利用長度先限制配置量，解碼後再次驗證實際 bytes；不可自動截斷。
- Lease 到期與 Dispatch 共用協調邊界。Renew Request 已送出但尚未被接受不代表已延長。
- Client request_timeout_ms 是本地等待期限；V1 沒有通用 `cancel` Method 來保證撤回已開始的 TX。
- Channel List 依 Frame 限制分頁；其他必要單一結果必須能放入 Frame，設定或內部資料超限時明確失敗，不輸出部分 JSON。

## 19. Reconnection 與 Server Restart

SDK 可以自動重建 TCP、協商、認證及依使用者選定政策恢復唯讀訂閱，但必須顯示 Connection State（連線狀態）、Replay 與 Gap；認證或版本不相容停止無效重試。

同 Instance／同 Epoch 且 Cursor 仍可用時 Replay；資料已淘汰時按 gap_policy 回覆；不同 Epoch 或 Instance 時不能將 Offset 接在一起。新的訂閱 ID 與新的 Session 不表示 TX 操作權恢復。

Server Restart 後：

- 新 `gateway_instance_id`，所有舊 Session、Lease、Fencing 授權及記憶體結果快取失效。
- 新開的 Serial Stream 使用新 Epoch；Ring 的舊資料不可假裝仍在。
- 持久 Recording（錄製）若存在，屬歷史檔案，不透過 V1 即時訂閱假裝續接舊程序。
- Candidate（候選）政策為 Binding 未確認，可先 RX；TX 需重新 Confirm 與取得新 Lease。
- `tx.status` 對舊 Instance 回 unknown／SERVER_RESTARTED，不能推論命令沒有執行。
- 舊 `tx.write` 不自動重送，不以新 TX ID 包裝補送。
