# 只讀互動式工作台

## 日常操作簡化（2026-11-07）

本輪依使用者核准建議，將日常啟動統一到 S，原有端點／完整設定等工具集中到 A。舊數字 1／2／3／4／6 仍可直接輸入以相容舊教學，但主畫面只呈現日常入口：

| 選項 | 操作 |
| --- | --- |
| S 開始監看 | 顯示上次設定的實際端點、錄製狀態／位置與人工 RX 恢復權限；Enter 才啟動 |
| L 查看本次錄製 | 直接使用本工作台最近一次成功啟動錄製的 Launcher 回報；雙路再選通道 |
| T 多窗格監看 | 選本機／遠端讀取／遠端管理，開啟獨立 UART 畫面與固定操作區；需可選 tui 依賴 |
| X TX 操作 | 明確使用獨立 TX 憑證，開啟目標核對、輸入／預覽及收據查詢；不自動啟動 Gateway |
| 5 瀏覽錄製 | 以日期分組同一 Capture 的 Channel，先選 Capture，雙路再選 Channel |
| A 進階工具 | 原裝置枚舉、手動監看／錄製、端點配置與完整 Gateway 設定入口 |
| Q／Enter | 離開工作台；不自動重開上次裝置 |

多窗格入口使用同一 SDK 認證及 Launcher；由 T 啟動的本機錄製也會回報本次 Capture，返回後可直接 L。遠端模式只清理 Client，不管理 Gateway。安裝、按鈕、快捷鍵及容量見 [多窗格 TUI](tui.md)。

TX 的一次設定與實機驗收見 [TX 工作台](tx-workbench.md)。X／uart tx 不沿用本機臨時 read Token、不自動提權；預設日常 S／T 仍維持原只讀入口。

S 頁面可 D 更換裝置：COM3 僅接收、COM3 可人工恢復、COM3＋COM4 可人工恢復，或從目前裝置清單互動選一至兩條。R 切換錄製開／關，C 還原完整設定自身的錄製選擇，M 指定進階 Gateway TOML；所有選擇都先顯示摘要，Enter 才啟動。Q 取消，不開啟裝置。監看中的 Q／Ctrl+C 只清理本次 Gateway，返回主畫面。

偏好檔記住設定來源與錄製選擇，工作台重啟後仍可重用；第一次預設 COM3 僅接收、錄製沿用設定（內建預設關閉）。不保存 Token、秘密內容、Capture 或搜尋結果，也不記住裝置已就緒。每次仍重新驗證設定、取得鎖並核對 Ready；從裝置清單選擇時自動建立新的無秘密端點 Profile，有序號者按原規則重新解析目前 COM，條件矛盾或模糊時停止，不能把名稱當作板子身分。參數及保存位置見 [設定規格](configuration.md#工作台操作偏好)。

L 的「本次」指本工作台最近一次已收到錄製就緒回報的 Capture，不是目錄排序最新項目。不錄製的監看不會產生新 Capture；啟動失敗不以其他目錄代替。重啟工作台後無本次回報，須用 5 明確選既有錄製。正常關閉仍由原檢查器確認 Footer，L 本身不保證錄製完整。

錄製清單以日期、通道／端點與「已收尾（未驗證）／未收尾」為主，完整路徑移到選定錄製後的 D。A／C／U／R 篩選與更新保留，先篩選 Channel 再依 Capture 目錄分組。資料夾與預覽掃描上限不變，完整性仍由 I 或實際搜尋／回看／匯出檢查；收尾標記不能當成 SHA-256 已驗證。

在錄製內按 S 搜尋後，輸入命中編號，Enter／V 可回看該資料流的命中前後各 30 秒；T 匯出同一區段，W 可改前後秒數（0～3600），Q 返回結果清單。跨 RX 區塊的關鍵字會把起始與完成命中的區塊時間一併納入區段，避免只看到後半段；時間無法解析或 Epoch 無效時不猜測，提示改用 F。Ctrl+C 取消回看會等待工作清理後返回工作台。

F 會先檢查整份錄製並列出資料流編號、首筆 RX 時間與資料量；可輸入編號，不需複製 Epoch。起迄欄位可輸入錄製起點後的分鐘，例如 5 與 10，或保留完整含時區時間。分鐘以整份 Channel 的首筆有效紀錄時間為起點，**不是選定 Epoch 的起點**；缺時間時明示不能使用相對分鐘。三欄 Enter 清除條件，Q 保留前次設定。此導覽摘要有界，不省略原全檔完整性掃描；中止會等待掃描工作結束。

T 提供根目錄 exports 下的新建議檔名，按 Enter 即匯出；M 可自訂，也可直接貼路徑。檔名含 UTC 時間及隨機識別，原匯出器仍以 x 模式建立，競爭或重名也不覆蓋。完成訊息顯示保存位置。來源 JSONL 不改寫，整份完整性警告仍保留在選取片段的摘要。

本輪新增 UX 測試採 Linux／Python／Fake Serial／真 TCP／PTY；尚未操作 Win11 的新 S／L、鍵盤／Ctrl+C、COM3／COM4 與公司 dxan 新流程。前一輪舊入口實機證據不視為此輪全部通過。

## 設計與範圍（2026-11-06）

使用者要求先開發、回家再測。本輪將既有 CLI 組成 `uart menu` 與薄雙擊入口 `run-workbench.cmd`，使用同步文字選單，所有監控仍經原 CLI／SDK／Launcher，不另外開 Serial 或重新實作協定。對應 Phase 2 的操作體驗切片；完整 TUI 與五至六條容量另行規劃。

工作台提供裝置清單、單／雙通道選擇後監看、選擇並錄製、使用既有端點 Profile，以及錄製目錄瀏覽、資訊、離線回看和文字匯出。`--recordings-dir` 預設 `recordings`，同時作為本次錄製根目錄及離線清單來源；每次重新枚舉，不自動開啟第一個裝置或最新錄製。可在選單中明確保存新 Profile；仍不覆寫既有檔案。

選單僅在 stdin／stdout 都是 TTY 時執行；輸入在 asyncio.run 之外，不留下等待 input 的背景執行緒。監控／回看中 Ctrl+C 等待既有流程清理後返回工作台；在選單提示時 Ctrl+C 離開整個工作台。Q／EOF 也可離開；EOF 不重試。一般操作錯誤回到選單，但 `LOCAL_CLEANUP_FAILED` 必須向外傳遞並結束工作台，不能清理不明還允許開下一個 Gateway。

錄製清單只掃描根目錄的 capture-* 與其 Channel 子目錄，數量有上限、最多顯示最近 50 個，超限時提供手動 Channel 目錄輸入；不遞迴掃描整顆磁碟。列表以目錄更新時間排序，並非完整性或來源板子的判斷，選定後仍交由原檔案檢查器驗證。顯示路徑會跳脫控制字元；所有選擇以結構化 argv 傳給同一 CLI，不使用 Shell Command。

原選 2～4 的本機 Gateway 仍使用每次新的臨時 Token；選 6 沿用完整 Gateway 設定的秘密參照，標準 Token 環境變數未設時才生成本次臨時憑證。本機入口不接管公司遠端 Gateway。遠端 RX 可使用下述 --remote 模式，或原有帶 Token 參照的 channels／watch。工作台不提供 Confirm、Lease 或 TX 操作。

## 前版進階入口與檢查原則（2026-11-07）

本輪依使用者指定順序完成候選項目 1、3、4。設計維持 CMD 薄入口與 Python Launcher：CMD 僅定位專案及 Python，設定驗證沿用 Server 純組裝函式，程序鎖／就緒／清理沿用原 Launcher，接收與人工重開沿用 SDK 工作區。未新增網路 API、Serial Server 或大型 TUI。

進階工具 A 的 **6** 可選完整 Gateway TOML：內建 COM3 只讀、COM3 RX 管理、COM3／COM4 RX 管理，或 M 輸入私人設定路徑。再選 C／Enter 沿用錄製設定、Y 啟用到工作台的錄製根目錄、N 本次停用、Q 取消。這與選 4 的端點 Profile 不同；所有覆寫只寫在暫存副本，不改原檔。

啟動會先取得全部目標端點鎖、確認 TCP Port 未占用，再啟動自己的 Gateway；認證權限、各 Channel Ready、端點與安全 UART 設定、啟用時的錄製健康度全部核對後才進入工作區。任一路啟動失敗會清理本次整組，不關閉既有 Gateway。Q／Ctrl+C／EOF 等待本次子程序收尾；清理不明為致命錯誤，不能接著開下一組。

工作區使用 R 查詢、O 1／O 2 加 Y 手動重開（設定須有 configure）、S 1／S 2 重新監看已停止且 ready 的通道。單路畫面保留原終端換行、退格與顏色；雙路標記來源並跳脫 CR／退格。這裡的 Q 會結束本次 Gateway；遠端模式的 Q 維持只清理 Client。工作區不提供 Confirm、Lease 或 TX。

**選 5 的錄製清單**現在顯示 Capture Header 時間、Channel／名稱／端點、最終收尾標記與 Epoch 預覽數。A 顯示全部、C 僅有收尾標記、U 未收尾、R 更新，仍需輸入編號或 M 明確選檔，不自動選最新。排序仍按目錄更新時間；Header 無時間時顯示未提供，不以排序時間冒充錄製起點。

每份預覽最多列舉 256 個目錄項目、讀取 256 KiB 順序資料及最後 64 KiB；單行上限 64 KiB。超限顯示至少若干 Epoch 或無法完成預覽。清單最多最近 50 個候選，外層目錄掃描最多 2000 項。有收尾標記只代表看見 Footer，**未驗證 SHA-256、身分與連續性**；I 才執行原完整檢查。未收尾可能仍在錄製或異常中止，回看／搜尋／匯出前會提示，僅明確 Y 繼續。直接 CLI 不互動確認，請自行確認已停止錄製。

選定 Channel 後：

| 選項 | 行為 |
| --- | --- |
| I | 完整檢查與 Epoch 摘要，永遠檢查整份錄製 |
| F | 設定 Epoch、起始及結束時間；三欄 Enter 清除條件，第一欄 Q 保留前次條件 |
| S | 輸入關鍵字，套用目前 F 條件，顯示命中時間／Epoch／byte 位移與安全文字預覽 |
| V | 套用 F，快速離線終端回看，Ctrl+C 返回工作台 |
| T | 套用 F 匯出至新文字檔，不覆蓋既有檔案 |

時間需含 Z 或明確時區，例如 `2026-11-06T19:05:00Z` 或 `2026-11-07T03:05:00+08:00`；兩端包含，以 RX 區塊時間選取整塊。空白時間不限制；缺少有效時間的區塊不納入時間篩選。篩選僅作用於 RX，狀態／缺口診斷及完整性仍涵蓋整份 Capture。沒有命中或資料達顯示上限，也不省略尾端雜湊與 Footer 檢查。

搜尋為 UTF-8 字面比對，區分大小寫、不用正規表示式；可跨連續 RX 與正常分段，不跨 Epoch、Binding Revision、狀態／缺口或排除區塊。相同關鍵字採不重疊命中。結果上限、區段 CLI 參數見 [設定規格](configuration.md#錄製搜尋與區段參數)，資料語意見 [錄製說明](recording.md#搜尋與區段回看2026-11-07)。

本輪新增入口已有 Linux 真子程序、TCP、PTY 與離線自動化證據，尚未執行 Win11 雙擊、鍵盤／Ctrl+C、實體 COM3／COM4 的新流程驗證；不能以舊入口通過代替。

## 回家操作

更新 work 分支後，在專案根目錄雙擊 `run-workbench.cmd`，或執行：

```powershell
.\.venv\Scripts\uart.exe menu
```

選 1 列出端點，2 選擇並監看，3 選擇並錄製，4 使用既有 Profile，5 瀏覽錄製，6 依 Gateway 設定整合啟動。單／雙通道仍由使用者明確選擇；選 3 的錄製存入指定根目錄下的新 Capture。選 5 選定一個 Channel 後，可重複檢查、回看及匯出；匯出必須指定新檔名。Q／直接 Enter 可返回或離開。

其他錄製位置可指定：

```powershell
.\.venv\Scripts\uart.exe menu --recordings-dir 'D:\uart-recordings'
```

測試順序為：用既有錄製檔檢查／回看／匯出，再用單 UART 錄製新資料，Ctrl+C 返回工作台，確認可重新啟動。最後於兩組設備齊備時另測雙 UART。自動化／PTY 不能代替 Win11 雙擊、主控台 Ctrl+C 與實體 USB 驅動驗證。

## 遠端自動認證補充（2026-11-07）

首次依 [認證初始化](authentication.md) 安裝固定來源後，`uart menu --remote` 自動使用 SDK 的預設讀取連線；`uart --access manage menu --remote` 明確選管理，`--connection` 選具名部署。Workbench 不另外讀取或保存 Token，R 觸發 SDK 重讀相同來源，失效不降級或提權。CLI 舊明確來源仍相容，以下原示範作為進階遷移方式。新 Windows ACL／SSH 工作台流程尚待實機驗證。

## 遠端模式（2026-11-06）

```sh
uart --host 127.0.0.1 --port 18081 --token-file <受保護的Token檔案> menu --remote
```

遠端模式只使用 SDK 連線既有 Gateway，第一次認證後列出有 read 權限的 Channel：ID、名稱、狀態、端點、錄製健康度及錯誤。輸入編號選擇；R 重新查詢或重新連線，正常清單 Q／Enter 離開。清單是上次查詢快照，不是持續更新的狀態；未就緒的 Channel 不建立訂閱。有 configure 與下述擴充能力時，可明確選擇單路 RX 重開。

選一個編號後 L／Enter 為即時接收，R 為最早仍保留的歷史＋即時接收，Q 返回。亦可依下節輸入兩個不同編號，同時監看最多兩條。使用現有終端過濾器與有界輸出；單路監看中 Ctrl+C 清理 Client 並返回清單，Gateway 保持執行。選單輸入處 Ctrl+C 結束工作台、退出 130，Q／EOF 正常退出 0。認證、連線或訂閱失敗，或查詢時所有通道都未就緒，會進入恢復選單：Enter 僅保持等待、不退出、不連線；R 才重新查詢。重新查到 ready 通道後恢復正常清單的 Enter 離開語意。

### 雙路同時監看（2026-11-07）

清單輸入 `1,2` 或 `1 2`，再選 L／Enter 即時或 R 歷史＋即時。只接收這次明確選擇的兩條，不自動加入其他通道；未就緒的一路先停留等待，另一路可正常監看。畫面每批／每行標明 Channel／名稱，各自保存 UTF-8／顏色狀態；CR／退格跳脫顯示，避免改寫來源標記或另一通道內容。這是合併文字畫面，沒有分割窗格或完整 TUI Framework。

| 指令（輸入後按 Enter） | 行為 |
| --- | --- |
| `R` | 查詢最新快照／權限，不重新訂閱或開啟 Serial；既有監看繼續 |
| `O 1`／`O 2` | 選擇工作區第一／第二路手動重開；需 configure、擴充能力、lost／faulted／closed 快照，再輸入 Y 確認 |
| `Y` | 僅在重開確認提示後有效；其他輸入取消該次操作，Q 可直接返回清單 |
| `S 1`／`S 2` | 對已停止且快照 ready 的一路手動重新監看即時資料；請先 R 更新；活動訂閱不重複建立 |
| Enter | 顯示目前狀態及操作說明，不連線或操作 Serial |
| `Q`／Ctrl+C | 清理雙路 Client 並返回外層清單，Gateway 繼續；按 R 查詢後再選，Q 離開工作台 |

O／S 的數字是本次工作區的第一／第二路，依進入時輸入的順序，與外層清單編號不必相同。等待確認、查詢與 Driver 重開期間，另一條訂閱持續接收。成功重開後只替該路建立監看連線，核對新快照並重播新 Epoch 仍保留的資料，再接即時；不接回舊 Epoch，也不重建另一條連線。失敗或結果不明不重試，先 R 查詢後再決定。重開等待中 Ctrl+C 也不代表 Server 已取消，返回後須先查詢結果。

每一路使用獨立 SDK Session／事件佇列，經既有 watch_client 核對 Instance／Revision／Epoch 與訂閱回覆，共用原有界 Writer；不新增 API。單路裝置／網路／快照錯誤只停止該路；無自動重連或失效後自動重新訂閱。R 發現不同 Instance 後禁止工作區內 S／O，必須 Q 返回並重新選擇。共享顯示失敗或容量不足時整組清理並明示錯誤，不能把缺資料當作正常顯示。

主控台採非阻塞輪詢：Windows 用 msvcrt 鍵盤介面，透過同一 Writer 顯示指令輸入；POSIX 保留原終端模式，以 select／單 byte 讀取完成指令。每次最多處理 128 字元，緩衝最多 128 字元，過長指令拒絕；沒有等待 input 的背景執行緒，也不把 UART 輸出視為指令。RX 持續輸出可能穿插指令提示，請輸入指令並按 Enter；不是固定位置的命令列。Windows 實際鍵盤、Ctrl+C 與視覺顯示仍須實測。

### USB 拔插與遠端恢復

USB 回到 Windows 枚舉清單，只代表端點再次可見。Gateway 目前不自動重開 Serial，原 Channel 在 device_lost 後仍為 lost。R 只重新連線／查詢 SDK 狀態，即使成功查詢同一 Gateway Instance，仍可能看到 DEVICE_MISSING。

本機 `menu` 的選 Port 流程擁有自己啟動的 Gateway，清理後可重新選擇並建立新程序。`menu --remote` 不管理 Gateway 程序；新版提供單通道手動 RX 重開：Gateway 須宣告 `channel.reopen_rx` 能力，該 Token 須有 read＋configure。選擇 lost／faulted／closed 通道後輸入 O，再明確 Y 確認；一般只讀 Token 不顯示操作，Server 也會拒絕呼叫。

操作前另建 SDK 連線並核對 Instance／Revision／Epoch；快照已變更時不開啟裝置，要求 R 重新選擇。成功時同一 Instance 下只有該 Channel 換成新 Epoch／unconfirmed，舊記憶體歷史清除，其他通道與錄製檔保留。成功後更新清單，由使用者再次選擇監看；失敗或結果未確認時不重試、不自動查詢，須按 R。請求可能已接受，不能把連線逾時當作未執行。核對原 Adapter 身分、關閉與 Driver 收斂規則見 [協定 9.2](protocol/v1.md#92-單通道手動-rx-重開擴充2026-11-06)。

舊 Gateway 沒有能力或目前 Token 沒有管理權限時，請由管理者操作單路恢復；全 Gateway 重啟僅作人工備援，須確認全部通道可中斷、沿用相同 Token，之後 R 查詢新 Instance。重啟不保留記憶體歷史。沒有背景自動重開，也不呼叫 Confirm、Lease 或 TX；Serial 參數與控制線設定不變。

每次查詢與監看各使用一條短期擁有的 SDK 連線，結束立即清理；輸入仍在事件迴圈之外。每次連線重新讀取 --token-file 或 --token-env（預設 UART_GATEWAY_TOKEN），更新 Token 來源後可按 R 重試，不將 Token 保存到工作台設定或輸出。

所選快照的 Instance／Binding Revision／Epoch 必須與新連線、查詢及訂閱回覆一致。不一致時取消訂閱、未顯示 RX，要求 R 更新並重新選擇；新 Token 若已無所選通道的 read 權限，也會拒絕並要求重新查詢。這個保護不能辨識同 Adapter 換接板子但未走 Binding 流程的情況。

--remote 與本機的 --recordings-dir 互斥。遠端選單不建立／停止 Gateway，不遠端修改錄製、UART 設定或取得 TX。錄製健康度是 Gateway 已回報的狀態，並非從 Client 啟用錄製。現有 run-workbench.cmd 保留本機入口。Win11 同機與 dxan 操作見 [Windows Quickstart](windows-quickstart.md)。
